## 発注受付フロー（メインフロー）

```
【お客様】
  │
  ├─ ログイン / 新規登録
  │       ↓
  ├─ 発注フォーム（OrderApp）
  │    ├─ サービス選択（養生 / 解体 / 産廃 / 清掃）
  │    ├─ 詳細入力（サービス別フォーム）
  │    ├─ 日程・現場情報入力
  │    ├─ 確認画面
  │    └─ 送信
  │         ↓
  │    Supabase に保存
  │    ① sites テーブル upsert（現場情報）
  │    ② cases テーブル insert（案件作成・KJ-xxx採番）
  │    ③ orders テーブル insert（case_id紐付け）
  │    ④ schedules テーブル insert
  │    ⑤ Storage アップロード（写真）
  │    ⑥ order_images テーブル insert
  │    ⑦ messages insert（LiBot「受け付けました！」）
  │         ↓
  └─ 注文履歴画面（HistoryApp）でステータス確認
           ↕ チャット（ChatScreen）で担当者と連絡
```

**ステータス:** ✅ 確認済み（全フロー実装済み）

## ステータス遷移フロー

```
発注完了
  ↓
【調整中】 ← 受付直後（黄）
  │
  ├→【日程確定】 ←── 管理者が確定（青）
  │     │
  │     ├→【日程変更相談中】 ←── お客様が日程変更依頼（紫）
  │     │     │
  │     │     └→【日程確定】（再確定）
  │     │
  │     ├→【キャンセル相談中】 ←── お客様がキャンセル依頼（薄赤）
  │     │     │
  │     │     └→【キャンセル】（管理者が確定）（赤）
  │     │
  │     └→【完了】 ←── 終了時刻過ぎで自動遷移（緑）
  │
  ├→【日程相談中】 ←── 管理者が調整中に設定（オレンジ）
  │     └→【日程確定】
  │
  └→【キャンセル】（調整中からも可能）
```

**ステータス:** ✅ 確認済み（7段階全て実装済み）

```

  受付からの経過時間:
  ├─ 残り12h以内 → カード薄黄

  ├─ 48h経過 → オレンジ
  ├─ 60h経過 → 濃オレンジ
  └─ 72h経過 → 赤点滅

  ↓
過去になっていた場合 → orders.status を「完了」に自動更新
```

## チャットフロー

```
【お客様側】                    【担当者側（AdminApp）】
  ↓ メッセージ送信                    ↓ メッセージ送信
  messages テーブルに insert          messages テーブルに insert
  from_role = 'user'                  from_role = 'staff'
       ↕ 3秒ポーリング ↕
  LiBot自動返答（0.9秒後）
  from_role = 'eli'
```

**LiBot自動メッセージ（5種類）:**

| トリガー | 送信内容 | 送信者 | ステータス |
|---|---|---|---|
| 発注完了時 | 「受け付けました！24時間以内に...」 | eli | ✅ 確認済み |
| 日程確定時（管理者操作） | 「【日程確定のご連絡】M月D日...」 | eli | ✅ 確認済み |
| キャンセル確定時（管理者操作） | 「【キャンセル承認のご連絡】」 | eli | ✅ 確認済み |
| キャンセル依頼時（お客様操作） | 「【キャンセルのご依頼】」 | eli | ✅ 確認済み |
| 日程変更依頼時（お客様操作） | 「【日程変更のご依頼】現在/希望日程」 | eli | ✅ 確認済み |

**通知方式:** 3秒ポーリング（Supabase Realtime は未使用）

## パスワードリセットフロー

```
ログイン画面
  ↓「パスワードをお忘れの方」クリック
ForgotScreen
  ↓ メールアドレス入力 → 送信
  Edge Function (send-reset-email)
  ↓ Resend API でメール送信
  ↓ メール内リンクをクリック
ResetPasswordScreen（URLハッシュからトークン取得）
  ↓ 新パスワード入力 → 更新
  sb.auth.updateUser({ password })
  ↓ signOut → ログイン画面へ
```

**ステータス:** ✅ 確認済み（全フロー実装済み）  
**依存:** Resendドメイン認証（markan.co.jp）⚠️ 要確認

## 現場情報更新フロー（お客様→管理者通知）

```
お客様が詳細画面で現場情報を編集・保存
  ↓
sites テーブル upsert（現場情報更新）
site_history テーブル insert（変更履歴記録）
order_change_logs テーブル insert（変更ログ記録）
  ↓
管理者の AdOrderCard に 📋 橙バッジ表示
  ↓
管理者が案件を開く → seen_by_admin = true に更新 → バッジ消去
```

**ステータス:** ✅ 確認済み（実装済み）

## 新規ユーザー登録フロー

```
LoginApp → 「新規登録」クリック
  ↓
RegisterApp
  Step1: メール・パスワード入力
  Step2: 氏名（姓/名）・ふりがな（姓/名）・電話番号
  Step3: 企業コード入力（CompanyPanel で発行された6桁コード）
  ↓
sb.auth.signUp（Supabase Auth ユーザー作成）
profiles テーブル upsert（name / name_kana / phone / company_id）
  ↓
企業コード照合（companies テーブル）
  ├─ is_active = false → 登録拒否
  └─ is_active = true  → 登録完了 → ログイン画面へ
```

**ステータス:** ✅ 確認済み（実装済み）
